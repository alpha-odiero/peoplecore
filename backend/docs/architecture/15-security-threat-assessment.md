# 15 — Security Threat Assessment

Scope: backend + data + object storage for P0/P1, with forward controls for P2–P7. Ratings are qualitative (L/M/H). Each scenario maps to a test in [doc 18](18-testing-strategy.md).

## 1. Threat scenarios

| #    | Scenario                                                                                             | Likelihood | Impact   | Mitigation                                                                                                                                                                    | Verification                                                               |
| ---- | ---------------------------------------------------------------------------------------------------- | ---------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| T-01 | Cross-tenant IDOR: attacker changes `employeeId`/`tenantId` in path/body to read another org's data. | H          | Critical | Tenant from authenticated context only; `whitelist: true` DTOs reject `tenantId`; tenant predicate in every repository query; RLS with `app.tenant_id`; 404 for out-of-scope. | Cross-tenant e2e tests, RLS test, DTO rejection test.                      |
| T-02 | Stolen refresh token replay.                                                                         | M          | Critical | Opaque token, SHA-256 at rest, rotation on use, reuse detection by `family_id`, full family revocation, audit + alert, HttpOnly/Secure/SameSite cookie.                       | Reuse test asserts family revocation + 401.                                |
| T-03 | Privilege escalation via role assignment or mass assignment.                                         | M          | Critical | `roles.manage`/`users.manage` required; tenant_admin grants restricted; DTO whitelist; permission_version increment + cache invalidation; system roles immutable.             | Authorization tests for every admin endpoint.                              |
| T-04 | Stale permissions after role revoke.                                                                 | M          | High     | Redis cache keyed by permission_version; increment on every role change and password reset; short TTL.                                                                        | Test revoke → next request 403.                                            |
| T-05 | SQL injection via search/sort/filter.                                                                | M          | Critical | Prisma parameterized queries; allowlisted sort/filter fields; no interpolated SQL; raw SQL confined to migrations.                                                            | Fuzz list endpoints with SQL payloads.                                     |
| T-06 | Sensitive field leakage (salary, national ID, DOB) in API, logs, audit or notifications.             | H          | High     | Field-level redaction map; encrypted columns; response DTO allowlist; Pino redaction paths; audit snapshot scrubber; no PII in event payloads.                                | Redaction tests across roles and log assertions.                           |
| T-07 | Private document exposed via public object URL or guessed key.                                       | M          | Critical | Private bucket, tenant-prefixed random keys, short-lived presigned URLs after permission check, no public ACL, key ownership verified on confirm/download.                    | Object-storage tests, URL expiry test, key enumeration test.               |
| T-08 | Malware upload / MIME spoofing.                                                                      | M          | High     | MIME + size validation before presign, checksum on confirm, scan status gate before download, AV scanner integration queue, quarantine status `infected`.                     | Upload tests with oversized/wrong MIME; scan-status gating test.           |
| T-09 | Invalid lifecycle transition / business-logic bypass (e.g. bulk terminate without checks).           | H          | High     | Central state machine in service only; 409 on invalid; version check; all mutations through service (no controller writes).                                                   | 7×7 transition matrix tests + concurrency test.                            |
| T-10 | Audit tampering: user edits/deletes audit or history rows.                                           | L          | Critical | DB role has INSERT/SELECT only; immutability triggers; append-only API; separate reporter role.                                                                               | Attempt UPDATE/DELETE as app role → DB error; no audit mutation endpoints. |
| T-11 | Duplicate event/job creates duplicate business records (double notification, double payslip).        | M          | High     | `eventId` unique, `jobId=eventId`, idempotency keys, unique natural keys, processed-marker checks.                                                                            | Duplicate-event and duplicate-job tests.                                   |
| T-12 | Account enumeration via login/forgot flows.                                                          | M          | Medium   | Generic 401/202 responses, constant dummy hash verification, uniform timing, rate limits.                                                                                     | Response/timing comparison tests.                                          |
| T-13 | Brute-force / credential stuffing.                                                                   | H          | High     | Rate limits, lockout, Argon2id, breached-password check `[ASSUMPTION]`, audit alerts on failure spikes.                                                                       | Rate-limit integration test.                                               |
| T-14 | CSRF on cookie-authenticated refresh.                                                                | M          | High     | SameSite=Strict, CSRF double-submit header, refresh endpoint accepts cookie only, Origin/Referer validation.                                                                  | CSRF test without token → 403.                                             |
| T-15 | XSS via stored employee notes or document names (frontend impact).                                   | M          | Medium   | Output encoding in frontend (out of backend scope), strict DTO validation, no HTML rendering of stored text, CSP headers at edge.                                             | Store-then-render test in E2E.                                             |
| T-16 | CSV injection / malicious import file.                                                               | M          | Medium   | Validate headers and cell types, escape `=+-@` prefixes on export, size/row caps (5MB/1000 rows) `[REF]`, import runs as restricted worker.                                   | Malicious CSV fixture test.                                                |
| T-17 | SSRF via future webhook/provider URLs.                                                               | L          | High     | Allowlist schemes/hosts, block private IP ranges, DNS revalidation, egress rules in prod.                                                                                     | Webhook config validation tests (P7).                                      |
| T-18 | Secrets leakage in source, logs, or errors.                                                          | M          | Critical | Env validation, secret manager, Pino redaction, error filter strips internals, CI secret scanning, no secrets in seeds.                                                       | Log scan test with seeded fake secret.                                     |
| T-19 | DoS via huge pagination, deep filters, or import floods.                                             | M          | Medium   | Page size cap, query timeouts, rate limits, job concurrency caps, payload size limits, connection pooling.                                                                    | Load test + oversized request test.                                        |
| T-20 | Payroll fraud / unauthorized pay changes (future).                                                   | L          | Critical | Maker-checker split permissions, locked periods, immutable payslips, change audit, reconciliation, jurisdiction adapters.                                                     | P3 security tests.                                                         |
| T-21 | Performance data exposure (future).                                                                  | M          | High     | Feedback visibility rules, calibration maker-checker, field encryption, strict scope checks.                                                                                  | P5 visibility tests.                                                       |
| T-22 | Backup/object-storage exposure.                                                                      | L          | Critical | Encrypted backups, restricted IAM, versioning, restore runbooks, separate reporting role.                                                                                     | Restore drill in staging.                                                  |
| T-23 | Race condition: two concurrent status changes or approvals.                                          | M          | Medium   | Row locks (`FOR UPDATE`), version checks, unique step constraints, 409 on conflict.                                                                                           | Concurrency tests.                                                         |
| T-24 | Malicious insider with DB access bypassing app.                                                      | L          | High     | RLS for app role, DB audit logging, least-privilege roles, no shared credentials, PAM/JIT access in prod.                                                                     | DB role permission audit.                                                  |

## 2. Security architecture controls summary

| Area             | Controls                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------ |
| Authentication   | Argon2id, JWT RS256/EdDSA 15 min, opaque refresh with hash + rotation + family revocation, MFA-ready, rate limits. |
| Authorization    | RBAC permission checks + ABAC scopes + field redaction; deny by default.                                           |
| Tenant isolation | Context-derived tenant, DTO whitelist, composite unique keys, query scoping, RLS.                                  |
| Data protection  | Encryption at rest for PII fields, TLS in transit, private object storage, secrets manager.                        |
| Integrity        | Immutable audit/history/payroll snapshots, version-based optimistic locking, outbox atomicity.                     |
| Availability     | Rate limits, bounded queries, bounded jobs, DLQ, circuit breakers, backups/PITR.                                   |
| Detectability    | Structured logs with correlation IDs, auth-failure alerts, outbox/DLQ metrics, audit trail.                        |

## 3. Compliance mapping (design intent, not certification)

| Requirement                  | Design response                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| Data minimization            | Explicit sensitive-field list; payloads carry IDs only; redaction by default.                          |
| Right to erasure / DSAR (P7) | Tenant + employee linkage throughout enables export/delete workflows; legal hold flag blocks deletion. |
| Retention                    | `retention_class`/`expires_at` on documents, audit retention job, object versioning.                   |
| Segregation of duties        | Maker-checker permissions for payroll/calibration; admin role boundaries.                              |
| Auditability                 | Immutable audit + data access events, request/correlation IDs, change snapshots.                       |
| Encryption                   | Field-level PII encryption, encrypted backups, TLS, secrets manager.                                   |
